## Changes

- Added `packages/solver`, the deterministic matching seam from spec #2. It
  defines its own `SolverCandidate` / `SolverVacancy` projections so ticket #4's
  `CandidateProfile` can adapt onto it later (see Remaining risk).
- Applied the confirmed weights — technical 30%, experience/evidence 25%,
  availability 15%, transport/accessibility 20%, salary/conditions 10% — with a
  per-dimension `scoreBreakdown` and reasons.
- Enforced mandatory skills, mapped mandatory requirements, schedule, salary,
  capacity, and geographic (commute and accessibility) hard constraints; a
  failure overrides the score and forces `not_currently_apt`.
- Mapped scores to `apt` (75–100), `apt_with_gaps` (50–74), and
  `not_currently_apt` (0–49).
- Implemented the one-point promotion rule: eligible only with peer evidence
  that no better eligible candidate exists, applied only with human approval.
- Made tie-breaking deterministic (score, failed-constraint count, vacancy id,
  candidate id) and independent of protected attributes and randomness.
- Added a Google Maps Distance Matrix router that falls back to an offline local
  matrix and records why; geographic reasons are always surfaced.
- Implemented the capacity-constrained assignment as a HiGHS MILP with a
  deterministic greedy fallback, wired into `nominate()`.
- Emitted `MatchDecision` as a JSON Schema 2020-12 contract validated with the
  shared Ajv instance from `@puente/domain`.
- Added fixtures and 76 Vitest tests.
