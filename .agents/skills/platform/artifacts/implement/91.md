## Summary

Built the durable chat turn path for the asynchronous chat turns API (parent spec
#90): a candidate submits one authenticated chat action to `POST /api/v1/chat/turns`,
receives a durable job (`202`), and a dedicated Node worker claims it with a lease,
executes the existing `handleChatTurn` seam, commits the optimistic session, and
acknowledges only after that commit.

## Risk Remaining

Delivery is at-least-once by design (an expired lease can re-run a turn); the
scheduler/wait adapter, backpressure (`429`/`503`), retry backoff scheduling, and
dead-letter retention from the parent spec are intentionally out of this tracer bullet.
