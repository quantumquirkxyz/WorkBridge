# api-contracts

When to use: Define the request and response contracts, versioning rules, compatibility boundaries, OpenAPI/JSON Schema, and breaking change detection for APIs — with explicit consumer obligations.

## Workflow

1. Identify the consumer jobs
2. Define request and response shapes
3. Choose the contract format
4. Design versioning strategy
5. Define compatibility boundaries
6. Plan error handling and retries
7. Security and auth in contracts
8. Documentation and discoverability

## Deliverables

- plan artifact

- side effects: none
- isolation: none; model tier: reasoning

Stop when: API contracts defined; versioning strategy explicit; breaking change policy and migration path named.
