# tdd

When to use: Test-driven development. Use when the user wants to build features or fix bugs test-first, mentions "red-green-refactor

## Workflow

1. Confirm seams
2. Write the failing test (red)
3. Write the passing code (green)
4. Repeat
5. Refactor (post-cycle)

## Deliverables

- implementation artifact

## Guardrails

- risk: low; trust tier: 1; approval required: no
- side effects: none
- isolation: none; model tier: reasoning

Stop when: Test-driven development complete; structured result returned; completion criteria checked.
