# sec-threat-modeling

When to use: Design and document threat models for software / systems — assets, threats, vulnerabilities, mitigations — using STRIDE or ATT&CK frameworks.

## Workflow

1. Define assets
2. Map architecture
3. Identify threats
4. Assess vulnerabilities
5. Design mitigations
6. Residual risk

## Deliverables

- model artifact

## Guardrails

- risk: low; trust tier: 1; approval required: no
- side effects: none
- isolation: none; model tier: reasoning

Stop when: Threat model saved; all assets mapped; risk register complete.
